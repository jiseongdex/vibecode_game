# Decisions: 캐릭터·미로 그래픽 다양화

- Date: 2026-09-29
- Status: Confirmed

## D01. 방향별 캐릭터 에셋 범위
- **Chosen**: 현재 탐험가 2종과 구조 동물 5종, 총 7종 모두 정면·뒷모습·왼쪽·오른쪽의 4방향 이미지를 제공한다. 각 방향은 별도 이미지로 제작한다.
- **Rationale**: 대표 캐릭터를 기준으로 각 캐릭터의 방향을 알아보기 쉽게 표현한다.

## D02. 대표 이미지 정리
- **Chosen**: 방향별 이미지 제작에 사용한 기존 대표 이미지 7장은 삭제한다. 탐험가 선택 화면과 구조 동물의 기본 이미지는 각 캐릭터의 새 정면 PNG를 사용한다.
- **Rationale**: 방향별 이미지가 완성되어 기존 대표 원본을 런타임에서 사용할 필요가 없다. 정면 이미지를 공통으로 사용해 화면 간 캐릭터 외형을 맞춘다.

## D03. 캐릭터 그림체와 시점
- **Chosen**: 기존 캐릭터의 얼굴·의상·색상 특징을 살리되, 머리와 후드가 전체 키의 약 60%를 차지하는 둥글고 폭이 넓은 SD 비율로 만든다. 짧은 타원형 몸통·작은 손발·몸에 가까운 망토를 사용하고, 살짝 위에서 내려다보는 시점의 정지 자세를 4방향에서 일관되게 유지한다. 크레이지 아케이드의 작은 화면에서 둥근 형태와 방향이 잘 읽히는 표현 방식을 참고한다.
- **Rationale**: 긴 다리·흩날리는 망토가 있는 초기 시안은 36px 셀에서 가늘고 동작마다 다른 캐릭터처럼 보였다. 넓고 단순한 실루엣은 4방향 전환을 자연스럽게 만든다.

## D04. 플레이어 방향 표시와 이동 효과
- **Chosen**: 여자·남자 플레이어 모두 마지막 방향 입력에 해당하는 이미지를 표시한다. 벽에 막힌 입력도 바라보는 방향을 바꾼다. 실제로 한 칸 이동했을 때에는 해당 방향의 왼발 앞/오른발 앞 자세를 짧게 교대해 발걸음을 보여 준다. 정지 시에는 기존 방향별 중립 자세로 돌아온다. 제자리 방향 전환에는 걷기 프레임을 재생하지 않는다.
- **Rationale**: 발이 번갈아 나오는 걷기는 한 장으로 합쳐진 PNG 전체를 CSS로 기울이는 것만으로 표현할 수 없다. 방향마다 두 발 자세가 있어야 작은 보드 셀에서도 정지·이동을 분명히 구분할 수 있다.

## D05. 구조 동물의 방향 표시
- **Chosen**: 구출 대기 중인 동물은 정면을 바라보고 정지한다. 구출 후 따라오는 동물은 각각 실제로 이동한 방향을 바라보며, 실제로 칸을 옮긴 동물에게만 짧고 작은 상하 점프 효과를 준다. 그 턴에 움직이지 않았거나 새로 합류한 동물은 뛰지 않는다.
- **Rationale**: 정지한 대상에는 기본 방향을 적용하고, 호송 중인 동물은 이동 궤적과 가벼운 통통 튀는 성격을 함께 표현한다.

## D06. 벽과 장애물 그래픽
- **Chosen**: 기존 얇은 선 형태의 벽을 제거하고 닫힌 경계마다 아기자기한 입체 장애물 블록 이미지를 배치한다. 논리 셀 중심과 경계 사이에 별도 시각 타일을 두어, 열린 경계는 통로이고 닫힌 경계는 장애물 타일이 된다. 숲·사탕·얼음·사막 테마마다 장애물 3종을 seed 기준으로 섞고 바닥 2종을 사용한다. 기존 미로 통로와 충돌 규칙은 유지한다.
- **Rationale**: 미로의 게임 규칙을 바꾸지 않으면서 보드의 시각적 깊이와 다양성을 높인다.

## D07. 맵 테마 선택
- **Chosen**: 숲·사탕·얼음·사막의 4개 테마 중 하나를 새 미로 생성 시 무작위로 선택한다. 같은 테마가 연속으로 선택되는 것도 허용한다.
- **Rationale**: 고정된 단계 구간 없이 각 단계에 서로 다른 분위기를 제공하고, 무작위성의 자연스러운 반복도 허용한다.

## D08. 테마와 미로 재시작·이어하기
- **Chosen**: 테마는 미로 생성 시 해당 미로의 seed를 기준으로 결정해 같은 미로에서 재도전하거나 저장된 게임을 이어할 때 유지한다. 새 미로를 만들면 새 테마를 다시 선택한다.
- **Rationale**: 동일 미로를 재시도할 때 시각 환경이 바뀌지 않도록 하고, 새 미로 생성 시에는 테마 선택을 다시 무작위화한다.

## D09. 기존 저장 데이터 마이그레이션
- **Chosen**: 버전 1 저장 데이터를 새 방향 정보가 포함된 형식으로 자동 변환하고, 해금 진행도·기록·현재 미로와 플레이 상태를 보존한다. 이전 저장에 없는 방향 정보는 기본 방향으로 채운다.
- **Rationale**: 그래픽 기능 추가가 기존 플레이 진행 상황이나 이어하기 데이터 손실로 이어지지 않게 한다.

## Codebase Findings
- 게임은 React·TypeScript·Vite이며 에셋은 `public/assets`의 로컬 PNG로 제공한다.
- 플레이어 방향은 현재 `GameState`에 저장되지 않고, 팔로워 상태는 위치 배열만 저장된다. 플레이어 방향 및 팔로워별 이동 방향을 상태·저장 스키마에 반영해야 한다.
- 미로는 이미 32비트 seed를 갖고 있고, 같은 미로 재도전에서 해당 미로 데이터를 재사용한다. 이 seed로 테마와 타일 변형을 재현할 수 있다.
- `.memory/current.md`의 이전 계획은 완료 상태이므로, 이 기능은 새 계획으로 시작해야 한다.

## Scope Notes
- 기존 미로의 생성·통로·충돌 규칙은 변경하지 않는다.
- 플레이어의 실제 발 교대에는 4방향 중립 PNG 외에 캐릭터당 각 방향의 왼발 앞/오른발 앞 PNG 8장, 총 16장을 추가한다. 완료된 중립 방향 PNG는 유지하고 원본 대표 이미지 7장은 삭제한다.
- 동물의 작은 점프에는 추가 프레임 PNG를 만들지 않는다. 기존 방향 이미지를 CSS로 위아래 움직이고 모션 감소 설정에서는 플레이어 프레임 교대와 동물 점프를 끈다.
- 외부 런타임 이미지 URL 없이 로컬 에셋을 사용한다.
