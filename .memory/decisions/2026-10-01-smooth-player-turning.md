# Decisions: 플레이어 방향 전환 부드럽게 표시

- Date: 2026-10-01
- Status: Confirmed

## D01. 방향 전환 표현
- **Chosen**: 기존 앞·뒤·좌·우 플레이어 이미지를 유지하고, 바라보는 방향이 바뀔 때 약 0.1초 동안 이전 모습에서 새 모습으로 짧게 전환한다. 새 방향·중간 각도 이미지는 생성하지 않는다.
- **Rationale**: 사용자가 기존 이미지로 전환 효과를 내는 방식을 선택했다. 현재 한 `<img>`의 `src`를 즉시 교체해 갑자기 바뀌는 느낌이 발생하므로, 이미지 교체 전후를 겹쳐 표시하면 이 문제를 줄일 수 있다.

## D02. 전환 시점과 반복 입력
- **Chosen**: `playerFacing`이 실제로 달라질 때에만 전환 효과를 시작한다. 이동 성공과 장애물 앞 방향 변경 모두 해당한다. 같은 방향의 반복 입력은 방향 전환 효과를 다시 시작하지 않고 기존 걷기 애니메이션만 수행한다. 짧은 시간 안에 다시 방향이 바뀌면 가장 최근 방향을 기준으로 전환을 갱신한다.
- **Rationale**: 게임 상태의 `MOVE`는 통행이 막혀도 바라보는 방향을 바꿀 수 있다. 방향이 유지되는 키 반복마다 전환을 재시작하면 이미지가 계속 흐릿하게 보일 수 있다.

## D03. 접근성과 초기 표시
- **Chosen**: 첫 렌더와 일시정지·복귀 후 같은 방향의 재표시에는 전환을 넣지 않는다. 사용자가 모션 감소를 설정했다면 기존처럼 즉시 새 방향을 표시한다.
- **Rationale**: 시작 화면에서 불필요한 번쩍임을 피하고, 이미 적용된 `prefers-reduced-motion` 처리와 일관되게 동작하게 한다.

## D04. 게임 규칙과 기존 걷기 프레임
- **Chosen**: `PlayerSprite`의 걷기 프레임 교체·이미지 사전 로드와 `MazeBoard`의 이동 좌표·카메라, 게임 상태·저장 형식은 유지한다. 방향 전환은 표시 효과로만 다룬다.
- **Rationale**: 원인은 방향 이미지의 즉시 전환이며 이동·충돌 데이터는 정상이다. 기존 걷기 프레임과 새 전환 효과가 겹쳐도 위치나 방향 상태가 변하지 않아야 한다.
