# Decisions: 단계 선택 화면의 랭킹·단계 분할 배치

- Date: 2026-10-06
- Status: Confirmed

## D01. 데스크톱 화면 구성
- **Chosen**: 단계 선택 페이지를 좌우 절반으로 나누어 왼쪽에 랭킹, 오른쪽에 현재 계정의 단계 선택 UI를 동시에 표시한다. 기존 `랭킹 보기` 버튼과 랭킹 전용 화면 전환은 제거한다.
- **Rationale**: 사용자가 요청한 핵심 배치다. 기존 `CampaignScreen`과 `LeaderboardPanel`을 함께 사용하고, 오른쪽 단계 경로는 좁아진 폭에 맞게 재배치한다.

## D02. 모바일 화면 구성
- **Chosen**: `단계 선택`과 `랭킹`을 탭으로 전환한다. 처음 열리는 탭은 `단계 선택`이다.
- **Rationale**: 사용자가 직접 선택한 모바일 동작이다. 두 영역을 좁은 화면에 동시에 넣지 않아 조작성을 유지한다.

## D03. 랭킹과 단계 데이터
- **Chosen**: 기존 인증 경로에 따른 간편 계정/Microsoft 랭킹 분리, 랭킹 정렬·현재 사용자 표시, 진행 상태·해금·재플레이 규칙을 유지한다. 기존 랭킹 API를 사용한다.
- **Rationale**: 현재 `App.tsx`, `LeaderboardPanel.tsx`, `CampaignScreen.tsx`에 필요한 데이터와 동작이 이미 구현되어 있다. 이번 요청은 화면 구성 변경이다.

## D04. 작업 순서와 배포 상태
- **Chosen**: 이번 화면 변경을 먼저 계획·구현한 뒤, 미완료 배포 작업 `P03-release/T01-cloudflare-entra-deploy`로 복귀한다. 현재 스테이징된 배포 파일은 화면 변경 작업의 커밋에 포함하지 않는다.
- **Rationale**: 사용자가 화면 변경을 우선하기로 선택했다. 배포 Task는 Microsoft Entra 앱 등록과 실사용 검증을 기다리는 상태다.

## D05. 상단 제목·계정 영역의 박스 제거
- **Chosen**: `동물 구출 대작전` 제목과 계정 정보가 있는 상단 `header`의 박스형 테두리·배경·그림자를 제거한다. 제목, 안내 문구, 계정 표시 이름, 로그아웃 버튼은 유지한다.
- **Rationale**: 사용자가 제거 대상을 상단 제목·계정 영역이라고 확인했다. 현재 외곽 박스 스타일은 `src/styles/global.css`의 `body > #root > main > header` 규칙에 있다.

## D06. 노트북 기본 화면과 스크롤 범위
- **Chosen**: `1440×900px` 브라우저 화면에서 로그인 방식 선택·간편/Microsoft 로그인, 단계 선택·랭킹, 게임플레이의 문서 세로/가로 스크롤이 생기지 않게 한다. 이 기준보다 작은 모바일·낮은 창에서는 내용과 조작 요소를 자르지 않도록 필요한 스크롤을 허용한다.
- **Rationale**: 사용자가 노트북 기준으로 `1440×900`을 선택했다. 기존 게임 화면 결정 `2026-10-02-laptop-fit-fixed-maze-view`도 같은 기준이며, 현재 `GameScreen`에 남은 높이 기준 미로 배율 계산이 구현되어 있다.

## D07. 단계 선택의 무스크롤 압축
- **Chosen**: `1440×900px`에서 오른쪽 단계 선택 영역 자체에도 스크롤이 생기지 않도록 20개 단계를 한 화면에 배치한다. 데스크톱은 오른쪽 절반 폭을 활용한 5열×4행 경로를 기본으로 하고, 버튼·글자·간격을 가능한 작게 조정하되 버튼의 조작 가능 크기와 잠금·완료·최고 기록 표시는 유지한다. 모바일에서는 기존 탭 방식과 접근 가능한 스크롤을 유지한다.
- **Rationale**: 사용자가 단계 선택 스크롤 제거와 단계 버튼의 최대한 작은 크기를 직접 요청했다. 앞선 계획의 고정 2열×10행은 1440×900 높이에 맞지 않으므로 수정해야 한다.

## D08. 랭킹 페이지네이션
- **Chosen**: 기존 API가 반환하는 상위 100명을 클라이언트에서 10명씩 최대 10페이지로 나눠 표시한다. `1440×900px`에서는 랭킹 영역 내부 스크롤도 없앤다. 이전/다음 페이지와 현재 페이지 표시를 제공하고, 상위 100명 밖의 내 순위는 페이지와 무관하게 확인할 수 있게 한다. 서버 API와 랭킹 정렬은 변경하지 않는다.
- **Rationale**: 사용자가 스크롤 대신 페이지네이션을 요청했다. 10명은 1440×900의 왼쪽 절반에서 제목·안내·조작 버튼을 함께 배치하기 위한 기본 페이지 크기다. 기존 API는 상위 100명 전체와 별도의 `current`를 이미 반환한다.

## D09. 로그인·게임 화면 조정 범위
- **Chosen**: 로그인 카드의 간격·글자 크기와 페이지 높이를 1440×900에 맞춰 조정하고, 게임 화면은 기존 반응형 미로 배율을 먼저 검증해 실제 남는 스크롤이 있을 때만 필요한 크기 규칙을 수정한다. 로그인 입력·오류 안내·게임 HUD·조작·팝업은 모두 접근 가능하게 둔다.
- **Rationale**: `LoginScreen.module.css`의 카드 높이는 콘텐츠에 따라 늘어난다. 게임플레이는 이미 별도 노트북 맞춤 작업이 완료되어 있으므로 중복 구현 없이 회귀 확인이 적절하다.

## 확인된 구현상 주의점
- 기존 `App.test.tsx`, `CampaignScreen.test.tsx`, `LeaderboardPanel.test.tsx`는 별도 랭킹 화면과 돌아가기 버튼을 검증한다. 새 동작에 맞게 수정해야 한다.
- 기존 계획의 랭킹 내부 스크롤 및 데스크톱 2열 단계 경로는 D07·D08로 대체한다. `/memory-execute` 전에 계획·Task 청사진을 갱신해야 한다.
- `src/App.tsx`에서 게임 세션이 시작되면 두 선택 영역 모두 게임 화면으로 교체되어야 하며, 게임에서 돌아오면 현재 랭킹을 다시 불러와야 한다.
