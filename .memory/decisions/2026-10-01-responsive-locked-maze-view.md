# Decisions: 반응형 화면틀 안의 일정한 게임 시야

- Date: 2026-10-01
- Status: Confirmed (사용자가 보이는 칸 수·비율 고정과 낮은 창에서도 가로·세로 스크롤 없는 축소를 선택)

## D01. 고정 대상과 이전 구현 정정
- **Chosen**: 화면틀 자체와 페이지는 반응형으로 유지한다. 고정할 것은 게임틀 안에서 보이는 맵의 시각 격자 칸 수와 플레이어·타일의 상대적인 크기다. 창이 작아지면 타일·플레이어·동물·장애물의 화면상 픽셀 크기를 같은 비율로 축소하고, 창이 커지면 같은 비율로 확대한다. `1240×840px`은 넓은 화면의 구성 기준이며 모든 창에서 강제하는 CSS 크기가 아니다.
- **Rationale**: 사용자가 이전 요청은 화면틀 고정이 아니라 내부 플레이 시야 고정이었다고 바로잡았고, 보이는 맵 칸 수와 플레이어·타일 비율을 고정하는 안을 선택했다. 이 결정은 `2026-10-01-fixed-maze-view.md`의 고정 픽셀 화면틀과 페이지 스크롤 규칙을 대체한다.

## D02. 화면틀 크기와 스크롤
- **Chosen**: 게임 화면틀과 주변 웹 UI는 창 너비와 사용 가능한 높이에 맞춰 줄어들어야 한다. 화면틀의 가로·세로 비율을 일정하게 유지하여 내부 시야가 늘어나거나 줄어들지 않게 한다. 게임틀 내부 스크롤과 문서의 가로 스크롤을 만들지 않는다. 높이가 낮은 창에서는 게임 화면틀을 남는 높이에 맞춰 추가로 줄여 일반적인 플레이 화면에서 세로 스크롤도 생기지 않게 한다.
- **Rationale**: 사용자는 화면틀과 전체 레이아웃이 반응형이어야 하며 스크롤이 생기지 않기를 요청했다. 가로와 세로를 독립적으로 늘리면 보이는 맵 칸 수가 달라지므로 같은 비율로 맞춰야 한다. 사용자가 낮은 창에서도 남는 높이에 맞춰 화면틀을 줄이는 안을 선택했다.

## D03. 내부 시야와 카메라
- **Chosen**: `1240×840` 기준 시야의 가로·세로 비율과 그때의 대략적인 보이는 칸 수를 모든 화면에서 유지한다. 카메라의 플레이어 중심 추적과 맵 끝 제한은 실제로 표시되는 화면틀과 타일 픽셀 크기를 같은 배율로 사용해 계산한다. 창 크기 변경만으로 맵의 추가 칸이 나타나거나 기존 칸이 사라지지 않아야 한다.
- **Rationale**: 현재 구현은 CSS 화면틀을 `1240×840px`로 강제하고 `cellSize=140px`를 고정해 작은 창에서 페이지 스크롤을 만든다. 화면틀과 타일을 같은 배율로 변경하면 내부 구성은 일정하게 보이면서 화면에 들어온다.

## D04. 범위와 검증
- **Chosen**: 고정 픽셀 화면틀과 `width: max-content` 플레이 영역을 제거하고, 작은 창의 페이지 스크롤을 없앤다. 이동·충돌·구출·저장 형식, 걷기 프레임, 모션 감소, 이미지 자산은 유지한다. 넓은 데스크톱·좁은 모바일·낮은 가로 화면에서 화면틀 경계, 보이는 맵 칸 수, 플레이어 비율, 카메라 이동, HUD·방향 버튼·오버레이 접근성과 스크롤 유무를 검증한다.
- **Rationale**: 이번 변경은 레이아웃과 보드 좌표의 배율 처리에 한정된다. 이전 구현의 주된 결함은 화면틀까지 고정해 전체 페이지가 넘친 것이다.
