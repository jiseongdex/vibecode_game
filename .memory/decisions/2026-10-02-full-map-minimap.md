# Decisions: 전체 지도 미니맵

- Date: 2026-10-02
- Status: Confirmed

## D01. 위치와 역할
- **Chosen**: 맵 틀 내부 오른쪽 하단에 작은 전체 지도를 고정 표시한다. 위치 확인용으로만 쓰며 클릭이나 드래그로 카메라를 이동하지 않는다.
- **Rationale**: 사용자가 맵 틀 안의 오른쪽 하단 위치를 지정했고, 읽기 전용 표시를 선택했다.

## D02. 지도 정보 공개
- **Chosen**: 탐험 여부와 관계없이 시작부터 전체 미로의 길과 벽, 모든 미구조 동물 및 탈출구 위치를 표시한다. 벽과 장애물은 장식 이미지 대신 선으로 간소화해 그린다.
- **Rationale**: 사용자가 전체 지형과 위치를 처음부터 공개하는 방식을 선택했고, 미니맵의 장애물은 선으로 간소화해도 된다고 명시했다.

## D03. 구조된 동물
- **Chosen**: 동물을 구조하면 해당 동물의 미니맵 표시를 제거한다. 따라오는 동물을 별도 동물 표시로 다시 추가하지 않는다.
- **Rationale**: 사용자가 구조 완료 후 표시 제거를 선택했다. 기존 `GameState.rescues[].rescued` 값으로 판별할 수 있다.

## D04. 현재 시야
- **Chosen**: 현재 화면에 보이는 맵 범위를 테두리로 표시하고, 테두리 바깥 영역에는 옅은 어두운 반투명 막을 씌운다. 바깥 영역의 동물·탈출구 표시는 계속 식별할 수 있게 한다. 플레이어 위치 점은 표시하지 않는다. 시야 테두리와 바깥 영역은 플레이어 이동과 화면 크기 변경에 따라 갱신한다.
- **Rationale**: 사용자가 플레이어 위치 점을 제외하고, 시야 바깥에 옅은 어두운 막을 씌우는 방식을 선택했다. 기존 `MazeBoard`는 플레이어 위치와 확대 비율에서 카메라 위치를 계산한다.

## D05. 기존 구조와 화면 크기
- **Chosen**: 기존 미로 데이터와 좌표계를 사용한다. 미니맵은 전체 미로를 항상 한 화면에 맞춰 그리며, 맵 틀의 크기 조정에 맞춰 작게 유지한다. 색상, 여백, 선 두께 및 동물·탈출구 표시 모양은 기존 화면 스타일과 가독성에 맞춰 구현 단계에서 정한다.
- **Rationale**: `MazeBoard`는 `GameState.maze`, `player`, `exit`, `rescues`를 이미 받고, `boardGeometry`에 지형 좌표 변환이 있으며, `GameScreen`은 맵 틀을 화면에 맞게 확대·축소한다. 별도 저장 데이터나 게임 규칙 변경이 필요하지 않다.

## 확인한 기존 동작
- `MazeBoard`의 카메라는 플레이어를 따라가며 맵 경계에서 멈춘다. 시야 테두리는 실제 카메라 오프셋과 뷰포트 크기를 반영해야 한다.
- `GameState`에서 동물과 탈출구 좌표는 그리드 좌표이며, 구조 여부는 `rescued`로 관리된다.
- 이번 단계에서는 구현 코드를 작성하지 않는다. 다음 단계는 `/memory-plan 전체 지도 미니맵`이다.
