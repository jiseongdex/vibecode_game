# Decisions: 두 로그인 방식과 분리된 랭킹의 무료 웹 배포

- Date: 2026-10-02
- Status: Confirmed

## D01. 배포 주소와 서비스 경계
- **Chosen**: 하나의 Cloudflare 배포 주소에서 `/microsoft`와 `/simple` 두 경로를 제공한다. 두 경로는 같은 게임 코드, API, DB를 사용한다.
- **Rationale**: 사용자가 두 접속 주소를 원하면서 별도 도메인 구매와 중복 배포는 원하지 않는다. 경로와 서버 측 인증 유형으로 로그인 화면과 랭킹을 분리한다.

## D02. 배포 플랫폼
- **Chosen**: Cloudflare Workers 무료 플랜에 정적 게임 파일과 API를 배포하고, Cloudflare D1 무료 플랜에 계정·진행·랭킹 데이터를 저장한다. 무료 기본 주소를 사용한다.
- **Rationale**: 사용자가 무료 서버와 DB를 원한다. 정적 파일, API, DB를 한 플랫폼에서 운영할 수 있다. 무료 한도 초과 시 서비스 요청이 실패할 수 있으므로 사용량을 확인한다.

## D03. 로그인 필수 및 경로 제한
- **Chosen**: 로그인하지 않은 방문자에게는 해당 경로의 로그인·가입 화면만 보여주고 게임 플레이와 랭킹 조회를 허용하지 않는다. `/microsoft`에서는 Microsoft 로그인, `/simple`에서는 간편 로그인만 허용한다. API도 인증 유형을 검사한다.
- **Rationale**: 사용자가 비회원 플레이를 허용하지 않도록 최종 정정했다. 프런트엔드 화면 분리만으로 랭킹 접근을 제한할 수 없으므로 서버에서도 강제한다.

## D04. Microsoft 계정 범위와 표시 이름
- **Chosen**: 개인 Microsoft 계정과 회사·학교 계정을 모두 허용한다. 랭킹에는 Microsoft 계정의 표시 이름을 사용한다. 이메일은 사용자 고유 식별자나 랭킹 이름으로 사용하지 않는다.
- **Rationale**: 사용자가 두 계정 범위와 표시 이름을 선택했다. 표시 이름은 실명일 수 있으므로 랭킹 화면에서 공개됨을 안내한다. 이름 변경과 동명이인을 고려해 내부 식별자는 Microsoft가 발급한 계정 식별 정보를 사용한다.

## D05. 간편 계정 가입 및 PIN
- **Chosen**: 방문자가 사용 가능한 닉네임과 정확히 숫자 4자리의 PIN을 직접 정해 가입한다. 간편 계정 안에서 닉네임은 대소문자·앞뒤 공백을 정규화해 고유하게 관리한다. PIN은 평문으로 저장하지 않고 서버에서 해시로 저장하며 가입·로그인 시도 횟수를 제한한다.
- **Rationale**: 닉네임과 4자리 PIN만 쓰고 싶다는 사용자 요구를 따른다. 가능한 PIN 조합이 1만 개뿐이므로 추측 공격을 줄이는 서버 측 제한이 필수다.

## D06. PIN 분실
- **Chosen**: PIN을 잊으면 기존 간편 계정을 복구하지 않고 새 닉네임으로 가입한다. 기존 기록은 기존 계정에 남는다.
- **Rationale**: 이메일 등 본인 확인 수단을 수집하지 않으므로 기존 계정 소유자를 안전하게 확인할 수 없다.

## D07. 로그인 유형과 데이터 분리
- **Chosen**: Microsoft 계정과 간편 계정은 서로 다른 사용자 유형으로 관리한다. 두 유형의 진행 상황과 랭킹은 합치지 않는다. 랭킹 API는 인증된 유형의 기록만 조회한다.
- **Rationale**: 사용자가 Microsoft 사용자끼리, 간편 로그인 사용자끼리만 순위를 보도록 요청했다.

## D08. 랭킹 기록과 정렬
- **Chosen**: 각 사용자에게 완료한 최고 단계와 그 단계의 개인 최단 클리어 시간을 `분:초`로 표시한다. 최고 단계 내림차순, 같은 단계에서는 해당 단계 최단 시간 오름차순으로 정렬한다. 미완료 사용자는 순위에서 제외한다.
- **Rationale**: 사용자가 지정한 순위 기준이다. 현재 게임은 20단계의 단계별 최단 클리어 시간을 이미 계산하고 있어 그 자료 구조를 활용할 수 있다.

## D09. 랭킹 범위와 기간
- **Chosen**: 로그인 유형별 전체 기간 상위 100명과 현재 사용자의 순위를 표시한다. 기록은 정기적으로 초기화하지 않는다.
- **Rationale**: 사용자가 전체 기간 집계와 표시 범위를 선택했다.

## D10. 무작위 미로 기록
- **Chosen**: 기존처럼 도전마다 생성되는 무작위 미로의 기록을 온라인 랭킹에 반영한다. 동일 단계에서도 미로 난도가 다를 수 있음을 수용한다.
- **Rationale**: 사용자가 공통 미로 방식 대신 기존 무작위 플레이의 기록 반영을 선택했다.

## D11. 온라인 기록 검증
- **Chosen**: 서버가 로그인 세션, 단계 해금 상태, 서버에서 발급한 도전 식별자와 시작 시각, 클리어 시간의 유효 범위, 중복 제출 여부를 확인한다. 비정상적으로 짧은 기록은 거부한다. 이동 경로 전체 재검증은 이번 범위에 포함하지 않는다.
- **Rationale**: 사용자가 기본 검증을 선택했다. 현재 클리어 판정과 시간 계산은 브라우저에서 이뤄지므로 기본 검증만으로 조작된 클라이언트의 부정 기록을 완전히 막을 수는 없다.

## D12. 기존 브라우저 저장 데이터
- **Chosen**: 처음 로그인한 계정은 1단계부터 시작한다. 기존 브라우저의 해금 단계, 최고 시간, 일시정지 중인 미로는 어느 로그인 계정에도 가져오지 않으며 온라인 랭킹에도 반영하지 않는다. 기존 로컬 데이터는 자동 삭제하지 않는다.
- **Rationale**: 사용자가 기존 기록을 가져오지 않기로 선택했다. 로컬 기록은 서버 검증이 불가능하다. 이전 프로젝트 결정의 로컬·Microsoft 병합 방침보다 이번 명시적 선택을 우선한다.

## D13. 계정 진행 상황 동기화
- **Chosen**: 로그인 후 얻은 해금 단계와 단계별 개인 최고 기록을 서버에 저장하고 다른 기기와 동기화한다. 진행 중인 미로와 일시정지 상태는 해당 기기에만 저장한다. 기기별 로컬 저장은 계정별로 분리한다.
- **Rationale**: 사용자가 동기화 범위를 선택했다. 현재 게임은 미로 전체를 `localStorage`에 저장하므로 일시정지 중인 미로의 서버 동기화는 데이터와 충돌 처리 범위를 크게 늘린다.

## D14. 기존 코드 기준선
- **Chosen**: 현재 Vite·React·TypeScript 클라이언트에 서버 인증, 계정 데이터, 랭킹 UI를 추가하는 방향으로 계획한다. 단계별 `bestTimeSeconds`, `unlockedStage`, 저장 스키마 v6를 기준으로 설계하되 기존 로컬 데이터를 온라인 계정에 자동 병합하지 않는다.
- **Rationale**: `src/game/campaignProgress.ts`, `src/hooks/usePersistedGame.ts`, `src/persistence/saveSchema.ts`, `src/persistence/saveStore.ts`에서 현재 모델과 저장 흐름을 확인했다. 로그인·서버·온라인 랭킹은 현재 구현되어 있지 않다.

## D15. 배포 준비 사항
- **Chosen**: Cloudflare 계정과 Microsoft Entra 앱 등록은 아직 준비되지 않았다. 후속 계획에 계정 생성, Microsoft 앱의 개인 및 조직 계정 허용 설정, 배포 주소의 리디렉션 URI 등록, 서버 비밀값 설정, 배포 및 실제 로그인 검증을 포함한다.
- **Rationale**: 사용자가 두 계정 모두 준비되지 않았다고 답했다. 실제 계정 로그인과 앱 등록이 필요한 단계는 계정 접근이 가능해진 뒤 수행한다.
