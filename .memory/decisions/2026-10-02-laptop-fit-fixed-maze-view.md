# Decisions: 노트북 화면에 맞추는 고정 미로 시야

- Date: 2026-10-02
- Status: Confirmed

## D01. 노트북 기준 화면과 세로 스크롤
- **Chosen**: 브라우저의 게임 플레이 영역이 `1440×900px`인 노트북 창을 기본 검증 기준으로 삼는다. 이 크기에서 HUD, 맵틀, 준비 상태의 시작 버튼을 한 화면에 배치해 게임 페이지에 세로 스크롤이 생기지 않게 한다.
- **Rationale**: 사용자가 `1440×900px`을 선택했다. 이 크기에서 맵틀을 가능한 크게 유지하면서 세로 스크롤은 없앤다.

## D02. 반응형 맵틀 배율
- **Chosen**: 맵틀은 사용 가능한 가로폭과 HUD·조작 요소를 제외한 세로 높이 중 더 제한적인 쪽에 맞춰 같은 비율로 확대·축소한다. 창 크기가 바뀌면 배율을 다시 계산한다. 가로폭이 남는 경우 맵틀을 가운데 배치한다. 맵틀 내부에 별도의 스크롤을 만들지 않는다.
- **Rationale**: 현재 `GameScreen`은 `width / 1250`만으로 배율을 계산하므로 맵틀이 노트북 창의 높이를 넘는다. 높이 제한도 반영해야 세로 스크롤 없이 맵틀 전체가 보인다.

## D03. 내부 게임 시야와 게임 동작
- **Chosen**: 현재의 맵틀 기준 `1250×850`, 내부 viewport `1240×840`, 타일 기준 `120px`을 유지한다. 창마다 맵틀·타일·플레이어·장애물·카메라를 동일한 배율로 표시해 보이는 타일 수 약 `10.33×7`과 플레이어/타일 비율을 고정한다. 미로 좌표, 이동·충돌·구출, 저장 형식은 변경하지 않는다.
- **Rationale**: 사용자가 창 크기에 따라 맵틀 크기만 조절하고 내부 시야는 고정하기를 요청했다. 현재 구현의 상대 비율과 카메라 계산은 공통 `sceneScale`을 사용한다.

## D04. 주변 UI와 검증 범위
- **Chosen**: 게임 진입 시 제목 숨김, 캠페인에서 제목 표시, `600px` 이하에서만 방향 버튼 표시, 현재 창에 고정되는 일시정지·결과 팝업은 유지한다. 준비·플레이·일시정지·결과 상태와 노트북·와이드·모바일 세로·낮은 가로 창에서 맵틀 배율, 고정 시야, 스크롤, 버튼 접근성을 검증한다. 매우 낮은 창에서 HUD와 조작 버튼의 물리적 높이가 화면보다 크면 내용 접근을 위한 문서 세로 스크롤을 허용한다.
- **Rationale**: 맵틀 높이에 쓸 수 있는 공간은 HUD와 상태별 버튼 높이에 따라 달라진다. 작은 창에서 조작 버튼을 잘라내지 않아야 한다.
