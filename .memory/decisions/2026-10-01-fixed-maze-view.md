# Decisions: 창 크기와 무관한 고정 게임 시야

- Date: 2026-10-01
- Status: Superseded by `2026-10-01-responsive-locked-maze-view.md` (사용자가 고정 화면틀·스크롤 해석을 바로잡음)

## D01. 고정할 플레이 화면
- **Chosen**: 실제 게임이 보이는 내부 영역을 현재 최대 데스크톱 화면에 가까운 `1240×840px`로 고정한다. 타일 픽셀 크기와 플레이어·구출 동물·장애물 이미지 크기도 창 크기 변화만으로 바뀌지 않게 한다. 현재 `TARGET_VISIBLE_COLUMNS = 7.8`, `TARGET_VISIBLE_ROWS = 6.0`에 따른 확대된 시야 감각을 유지한다.
- **Rationale**: 지금은 `MazeBoard`가 뷰포트의 실측 너비·높이로 `cellSize`를 다시 계산해 창을 조절할 때 타일과 플레이어 크기가 달라진다. 사용자는 내부 플레이어와 맵 시야를 항상 일정하게 유지하기를 원하며, 기준으로 `1240×840px`를 선택했다. 기존 `2026-10-01-zoomed-maze-viewport.md`의 D07 중 창 크기에 따른 내부 타일 재계산 규칙을 이번 결정으로 갱신한다.

## D02. 작은 창과 외부 레이아웃
- **Chosen**: 브라우저 창이 고정 플레이 영역보다 작아지면 게임 내부를 축소하거나 잘라 보이지 않는다. 고정 크기의 전체 플레이 영역에 페이지 스크롤로 접근하게 한다. 게임 바깥 제목·HUD·방향 버튼 등 웹 UI의 반응형 배치는 유지한다. 게임틀의 테두리는 고정 플레이 영역을 감싸도록 두어 내부 화면과 어긋나지 않게 한다.
- **Rationale**: 사용자가 작은 창에서 '게임 내부 크기 유지, 페이지 스크롤 허용'을 선택했다. 1240×840px 내부 시야와 플레이어의 실제 표시 크기를 동시에 유지하려면 작은 창에는 스크롤이 필요하다.

## D03. 카메라와 게임 규칙
- **Chosen**: 카메라의 플레이어 추적과 맵 끝 위치 제한은 고정된 내부 시야 크기를 기준으로 계산한다. 창 크기 변경만으로 카메라가 다시 줌하거나 새로운 맵 영역을 더 보여주지 않는다. 미로 생성·충돌·이동 속도·구출 동물 추적·저장 형식은 유지한다.
- **Rationale**: 변경 대상은 보드의 화면 기하와 CSS 배치이며 게임 상태와 진행 규칙은 이미 원하는 동작을 제공한다.

## D04. 검증
- **Chosen**: 넓은 창과 작은 창에서 동일한 `cellSize`, 플레이어 표시 크기, 플레이어 중심 카메라의 시야 범위를 확인한다. 작은 창에서는 전체 고정 영역에 스크롤로 접근할 수 있어야 하며, 플레이어 이동 후에도 카메라 추적·끝 제한이 유지되어야 한다.
- **Rationale**: 현재 `MazeBoard.test.tsx`는 좁은 뷰포트에서 `cellSize`가 `40px`로 감소할 것을 기대하므로 새 고정 크기 결정에 맞게 검증을 바꿔야 한다.
