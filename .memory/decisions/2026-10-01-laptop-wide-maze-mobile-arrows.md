# Decisions: 노트북 가로폭에 맞춘 맵틀과 작은 화면 전용 방향 버튼

- Date: 2026-10-01
- Status: Confirmed

## D01. 고정할 게임 플레이 시야
- **Chosen**: 기존 `1240×840` 기준의 가로·세로 비율과 보이는 맵 칸 수, 플레이어·타일의 상대 비율을 유지한다. 화면 크기에 따라 맵틀·타일·플레이어·카메라를 같은 배율로 확대하거나 축소한다. 게임 좌표와 저장 데이터는 바꾸지 않는다.
- **Rationale**: 사용자가 플레이 시야 고정을 다시 요청했고, 앞선 [반응형 시야 결정](./2026-10-01-responsive-locked-maze-view.md)에서 고정 대상을 맵 칸 수와 상대 비율로 확정했다.

## D02. 노트북의 맵틀 가로폭
- **Chosen**: PC와 노트북에서 방향 버튼을 위한 옆 공간을 없애고, 맵틀이 페이지의 사용 가능한 가로폭을 최대한 사용하게 한다. 다만 고정 시야 비율과 스크롤 없는 플레이 화면을 우선하여, 창 높이가 부족하면 높이에 맞는 배율까지만 확대하고 남는 좌우 공간을 허용한다. 기존 화면 배율 상한 `1`과 게임 화면의 `1400px` 최대 너비가 가로폭 사용을 불필요하게 제한한다면 제거한다.
- **Rationale**: 사용자가 노트북 창에 맞춰 맵틀을 가로 페이지 최대치까지 넓히길 원하면서도, 높이가 부족한 경우에는 고정 시야와 스크롤 없음이 우선인 방식을 선택했다.

## D03. 화살표 버튼 표시 조건
- **Chosen**: 현재의 키보드 방향키 모양 버튼을 화면 너비 `600px` 이하에서만 표시한다. 너비가 `600px`을 넘으면 PC와 낮은 가로 창에서도 숨기고, 실제 키보드의 방향키/WASD 이동은 유지한다. 모바일 버튼의 클릭·비활성화 동작은 유지한다.
- **Rationale**: 사용자가 세 가지 표시 조건 중 `600px` 이하만 표시하는 방식을 선택했다. 기존 코드도 `600px`을 모바일 레이아웃 경계로 사용한다.

## D04. 화면 상태와 검증 범위
- **Chosen**: 준비 상태의 시작 버튼은 PC에서도 접근 가능하게 배치한다. `ready`, `playing`, `paused`, `won`, `lost`에서 맵틀과 HUD·시작 버튼·팝업이 화면 안에 남아야 한다. 모바일 방향 버튼을 위한 세로 공간은 버튼이 표시될 때에만 예약한다. 데스크톱·노트북·`600px` 경계 양쪽·모바일 세로·낮은 가로 창에서 맵 시야, 방향 버튼 표시, 키보드 입력, 문서 스크롤을 확인한다. 캠페인 화면과 게임 규칙은 변경하지 않는다.
- **Rationale**: 방향 버튼을 숨기기만 하고 빈 공간을 남기면 요청한 맵틀 확대가 이루어지지 않는다. 기존 플레이 레이아웃은 상태에 따라 시작 버튼과 오버레이를 별도로 표시한다.
