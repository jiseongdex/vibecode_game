# 결정 사항: 렌더 칸 단위 이동

- 날짜: 2026-09-30
- 상태: 확정

## D01. 이동 단위
- **결정**: 기존 2N+1 렌더 격자를 실제 이동 좌표 격자로 사용한다. 한 번의 키 입력은 상하좌우 인접 렌더 칸 한 칸만 이동한다.
- **이유**: 바닥과 장애물을 같은 크기의 개별 칸으로 취급해 화면상 한 칸 이동과 입력 한 번을 일치시킨다.

## D02. 통로와 충돌
- **결정**: 큰 바닥 칸 중심과 벽이 없는 통로 연결 칸만 이동 가능하다. 벽 장애물이 놓인 연결 칸과 교차점 장식 칸은 막힌다. 각 이동 단계에서 기존 방향 전환·벽 충돌·발 애니메이션 동작을 유지한다.
- **이유**: 기존 미로 위상과 벽을 유지하면서 열린 연결 칸을 독립적인 이동 한 칸으로 만든다.

## D03. 출구·구출 대상·동행 동물
- **결정**: 출구와 구출 대상은 기존의 큰 바닥 칸 중심에만 배치한다. 동행 동물은 플레이어가 이동할 때마다 이전 위치를 한 칸씩 따라온다.
- **이유**: 목표 위치를 읽기 쉽게 유지하고 동행 동물도 새 이동 단위와 같은 격자에서 움직이게 한다.

## D04. 제한 시간
- **결정**: 우선 현재 스테이지별 제한 시간을 유지한다. 새 이동 방식으로 플레이해 본 뒤 필요하면 조정한다.
- **이유**: 실제 플레이 속도와 난이도를 확인한 뒤 시간 제한을 조정한다.

## D05. 출구 이미지 투명도
- **결정**: 출구 이미지의 알파 투명도를 유지한다. 출구 컨테이너의 불투명 배경색을 제거하고, 잠김 표시는 회색 필터, 해금 표시는 투명 배경 위 그림자 등으로 표현한다.
- **이유**: 출구 이미지 가장자리와 배경이 미로 바닥을 가리지 않게 한다.

## D06. 저장 형식
- **결정**: 새 위치 좌표를 사용하는 저장 형식은 v4로 올리고 이전 v3 저장은 마이그레이션하지 않는다.
- **이유**: 개발 단계에서는 저장 데이터 변환을 유지할 필요가 없다는 기존 결정을 따른다.

## D07. 기록 및 반복 입력
- **결정**: 스테이지별 최고 클리어 시간만 기록한다. 짧은 키 입력은 한 칸만 이동하고, 키를 계속 누르면 500ms 대기 후 최소 160ms 간격으로 반복 이동한다. 키를 놓거나 창 포커스를 잃으면 뒤늦은 이동을 실행하지 않는다.
- **이유**: 시간 기록만 유지하고, 한 번의 탭이 자동 반복으로 여러 칸 이동하는 문제를 막으면서 연속 이동을 지원한다.

## D08. 스프라이트 크기 기준
- **결정**: 플레이어와 구조 동물 스프라이트는 기존 크기를 유지한다. 새 이동 칸인 작은 렌더 칸의 140%, 즉 기존 큰 바닥 칸의 70% 크기다.
- **이유**: 기존에 결정한 캐릭터 크기와 시각적 비율을 유지한다. 스프라이트가 작은 통로 칸 여러 개에 걸쳐 보일 수 있다.
