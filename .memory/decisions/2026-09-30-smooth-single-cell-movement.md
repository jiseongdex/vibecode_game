# 결정 사항: 한 칸 이동과 부드러운 캐릭터 표현

- 날짜: 2026-09-30
- 상태: 확정

## D01. 격자 이동과 벽 충돌
- **결정**: 이동 입력 한 번마다 플레이어는 논리 미로 칸을 최대 한 칸 이동한다. 닫힌 벽과 미로 경계는 좌표 이동을 막는다. 이동이 막혀도 플레이어는 입력 방향을 바라본다.
- **이유**: 칸 단위 미로 규칙을 유지하고 장애물 통과를 막는다.

## D02. 키보드 반복 입력
- **결정**: 키를 누르는 동안 브라우저가 보내는 반복 `keydown` 이벤트를 받는다. 최초 입력은 즉시 한 칸 이동하며, 반복 이동은 누른 시점부터 500ms가 지난 뒤 시작하고 160ms보다 빠른 반복 입력은 건너뛴다. 키를 놓거나 창 포커스를 잃은 뒤에 추가 이동을 대기열에서 실행하지 않는다.
- **이유**: 짧게 키를 눌렀을 때 반복 입력이 추가 이동처럼 보여 두 칸씩 움직이는 문제를 막고, 길게 누를 때는 걷기 애니메이션 속도에 맞춰 연속 이동하게 한다.

## D03. 벽 앞 발 애니메이션
- **결정**: 벽이나 경계에 막혀도 누르고 있는 키의 반복 입력마다 입력 방향의 걷기 발 애니메이션을 반복한다. 키 반복 입력이 멈추면 애니메이션도 멈춘다.
- **이유**: 장애물을 통과하지 않으면서 해당 방향으로 계속 걸으려는 모습을 표현한다.

## D04. 캐릭터와 구출 동물 크기
- **결정**: 플레이어, 구출 동물, 동행 동물을 논리 미로 칸 너비의 약 70% 크기로 표시한다.
- **이유**: 각 캐릭터 주위에 칸의 여백을 보이고 플레이어와 동물 크기를 통일한다.

## D05. 이동 부드러움과 이미지 안정성
- **결정**: 완화된 CSS 변환으로 캐릭터가 칸 사이를 이동하는 모습을 보간하고 기존 보드 카메라 전환과 맞춘다. 방향·걷기 이미지가 바뀌어도 스프라이트 요소를 유지한다. 이미지 요소를 키로 다시 만들지 말고 필요한 스프라이트를 미리 불러와 전환 시 깜박임을 막는다.
- **이유**: 캐릭터를 부드럽게 움직이고 이미지 전환 중 빈 프레임이 보이지 않게 한다. 초기 속도는 기존 보드 전환 시간인 160ms를 기준으로 맞춘다.

## D06. 이동 애니메이션 신호
- **결정**: 입력 시도와 애니메이션 프레임은 렌더링 전용 임시 상태로 추적한다. 게임 상태, 세이브 데이터, 기록에는 이동 횟수를 저장하지 않는다.
- **이유**: 발·동행 동물 애니메이션을 갱신하는 데 이동 횟수 통계는 필요하지 않다.

## D07. 클리어 기록 항목
- **결정**: `moveCount`를 게임 상태, 화면, 기록, 세이브 데이터에서 제거한다. 스테이지별 클리어 기록에는 최고 클리어 시간(`bestTimeSeconds`)만 남긴다. 개발 단계이므로 이전 로컬 세이브를 마이그레이션하지 않는다. 새 저장 형식만 읽고 구형 저장 데이터는 복원하지 않는다.
- **이유**: 원하는 성과 기록은 각 미로를 클리어하는 데 걸린 시간뿐이다. 이동 횟수는 HUD·결과 화면·기록에 표시하지 않는다. 개발 단계에서는 과거 세이브 변환을 유지하지 않고 새 스키마로 단순하게 진행한다.
