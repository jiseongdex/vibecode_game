# Decisions: 좁은 길 방향 전환과 걷기 이미지 크기 안정화

- Date: 2026-10-02
- Status: Confirmed

## D01. 이동 속도와 방향 전환 방식
- **Chosen**: 현재 시각 격자 한 칸 이동, 키를 누른 즉시 이동, 110ms 반복 주기와 120ms 화면 전환을 유지한다. 좁은 사이길로 꺾을 때는 새 방향 입력을 짧게 예약하여 입구에 도달하면 회전한다.
- **Rationale**: 현재 속도는 사용자가 만족하지만, `useKeyboardMovement`가 동시에 누른 방향키마다 별도 반복 타이머를 실행하여 갈림길 진입 타이밍을 맞추기 어렵다. `gameReducer`는 정수 격자 좌표와 벽 충돌을 사용하므로 연속 좌표 보정이나 이동 속도 변경 없이 입력 우선순위를 조정하는 것이 맞다.

## D02. 회전 예약 조건과 범위
- **Chosen**: 진행 방향키를 누른 상태에서 그 방향과 직각인 새 방향키를 누르면, 새 방향으로 즉시 이동 가능한 경우 바로 회전한다. 새 방향이 막혀 있고 현재 진행 방향으로 한 칸 더 이동하면 입구가 열리는 경우에만 기존 방향으로 그 한 칸을 이동한 뒤 새 방향으로 회전한다. 그보다 먼 입구를 찾기 위해 예약을 유지하지 않는다.
- **Rationale**: 사용자가 입구 가장자리에 걸렸을 때만 자연스럽게 정렬되길 선택했고, 보정 거리를 현재 위치에서 한 칸 뒤의 입구로 제한했다. 이 동작은 충돌 판정을 우회하거나 캐릭터를 통과 불가능한 칸으로 이동시키지 않는다.

## D03. 여러 키와 예약 취소
- **Chosen**: 회전을 기다리는 동안 기존 방향으로 이동을 이어가되, 새 방향이 열리는 첫 칸에서는 새 방향 입력을 우선한다. 새 방향키를 놓거나, 창 포커스를 잃거나, 이동이 비활성화되면 예약을 취소한다. 단일 방향 입력, 반대 방향 전환, 화면 방향 버튼의 한 번 누르기 동작은 기존 방식으로 처리한다.
- **Rationale**: 사용자가 기존 방향키를 누른 채 새 방향키를 누르고, 첫 진입 가능한 칸에서 회전하는 조작을 선택했다. `useKeyboardMovement`에는 키 해제·포커스 상실·비활성화 시 반복 타이머를 정리하는 경로가 이미 있다. 화면 방향 버튼은 `DirectionControls`의 클릭 입력이라 누른 키를 유지하는 회전 예약 대상이 아니다.

## D04. 걷기 이미지 수정 범위와 크기 기준
- **Chosen**: 남녀 캐릭터 각각 네 방향의 걷기 A/B 이미지, 총 16개 PNG의 실제 불투명 그림 크기를 같은 캐릭터·방향의 기본 이미지에 맞춘다. 발이 바닥에 닿는 위치를 기준으로 정렬하고 몸 전체의 보이는 높이를 맞춘다. 손발의 걷기 자세 차이는 유지한다.
- **Rationale**: 사용자가 처음 발견한 현상은 여자 캐릭터가 아래쪽 장애물 앞에서 제자리 걸음을 할 때지만, 모든 걷기 프레임을 함께 맞추기로 범위를 확정했다. 파일 캔버스는 모두 1254×1254로 같아도 내부 그림 크기는 다르다. 기존 측정에서 여자 앞모습의 실제 그림 높이는 기본 1011px, 걷기 A 1033px, 걷기 B 1084px이다.

## D05. 이미지와 게임 표시의 유지 조건
- **Chosen**: 캐릭터 디자인·색·소품·투명 배경과 걷기 A/B의 서로 다른 발 자세를 보존한다. 막힌 상태의 제자리 걷기, 정상 이동의 걷기, 방향 전환 효과를 유지한다. 플레이어 표시 상자의 1.6칸 크기와 위치, 벽 충돌, 카메라 및 저장 형식은 이미지 크기 문제를 해결하기 위해 변경하지 않는다.
- **Rationale**: `PlayerSprite`는 기본 PNG와 걷기 PNG를 교체하고, `MazeBoard`는 막힌 이동에도 걷기 프레임을 재생한다. 표시 상자의 크기가 일정하다는 기존 DOM 테스트만으로는 PNG 내부 그림의 크기 차이를 잡을 수 없다. `2026-10-01-blocked-in-place-walk.md`의 제자리 걷기 결정은 유지하며, 그보다 이른 `2026-10-01-blocked-player-size.md`의 제자리 걷기 중단 결정은 다시 적용하지 않는다.

## D06. 확인 기준
- **Chosen**: 두 방향키를 겹쳐 누를 때 현재 칸과 한 칸 앞 입구에서의 회전, 더 먼 입구에서는 예약하지 않는 동작, 키 해제·포커스 상실·일시정지 시 취소를 확인한다. 남녀 네 방향에서 기본·걷기 A/B 이미지의 보이는 높이와 발 기준선이 일정한지 이미지 자체와 게임 화면에서 확인한다. 장애물에 막혀 있을 때 제자리 걷기와 현재 이동 속도가 유지되는지도 확인한다.
- **Rationale**: 회전 보정은 입력 타이밍의 문제이고 크기 출렁임은 PNG 내부 여백의 문제다. 각각 입력 동작과 실제 이미지 범위를 확인해야 한다.

## 코드 근거와 단계

- `src/hooks/useKeyboardMovement.ts`: 방향키·WASD의 누름, 110ms 반복, 해제 및 포커스 상실 처리.
- `src/components/GameScreen/GameScreen.tsx`: 이동 시도 횟수와 게임 상태 전달.
- `src/game/gameState.ts`, `src/game/mazeGrid.ts`: 한 칸 이동과 벽 충돌 판정.
- `src/components/Player/PlayerSprite.tsx`, `src/components/MazeBoard/MazeBoard.tsx`: 기본·걷기 이미지 선택과 제자리 걷기.
- `public/assets/players/player-{girl,boy}-{front,back,left,right}-walk-{a,b}.png`: 크기 보정 대상.
- 이 파일은 `/grill-me` 인터뷰 결과다. 구현과 이미지 교체는 `/memory-plan` 및 `/memory-execute` 단계에서 진행한다.
