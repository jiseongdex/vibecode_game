# 미로 구출대

React·Vite 기반의 20단계 랜덤 미로 게임입니다. 단계마다 새로운 미로가 생성되며, 모든 동물을 구출한 뒤 탈출구에 도착하면 다음 단계가 열립니다. 후반 단계에서는 최대 다섯 동물을 구출해야 합니다.

## 실행과 검증

Node.js와 npm을 준비한 뒤 프로젝트 루트에서 실행합니다.

```bash
npm install
npm run dev
```

브라우저에 표시된 로컬 주소를 열면 됩니다. Windows PowerShell에서 스크립트 실행 정책 때문에 `npm`이 막히면 `npm.cmd`를 사용하세요.

```bash
npm test -- --run
npm run lint
npm run build
```

## 이미지 파일

게임 이미지는 `public/assets/maps/`(맵 바닥·벽·출구), `public/assets/players/`(탐험가), `public/assets/animals/`(구조 동물)에 로컬 PNG로 저장합니다.

탐험가와 동물은 이동 방향에 따라 앞·뒤·왼쪽·오른쪽 이미지로 바뀝니다. 탐험가는 실제로 한 칸 이동할 때 두 발 자세가 짧게 교대하고, 이미 따라오는 동물은 움직인 경우에만 가볍게 뜁니다. 모션 감소 설정을 켜면 이 효과를 재생하지 않습니다.

미로를 새로 만들 때마다 숲·사탕·얼음·사막 중 한 테마가 seed에 따라 선택됩니다. 단계 구간에 고정되지 않으며 같은 테마가 연속으로 나올 수도 있습니다. 같은 미로를 다시 시도하거나 저장된 게임을 이어하면 테마와 바닥·벽 배치가 그대로 유지됩니다. 기존 저장 데이터도 자동으로 이어받습니다.

## 게임 규칙과 조작

- 단계 선택 화면에서 열린 단계를 고르고 `시작하기`를 누릅니다. 이미 완료한 단계도 다시 플레이할 수 있습니다.
- 방향키 또는 화면의 방향 버튼으로 이동합니다. 벽은 통과할 수 없습니다.
- 동물들을 모두 구조해야 탈출구가 열립니다. 시간이 0이 되기 전에 탈출구까지 가야 합니다.
- 시간 초과 시 같은 미로를 다시 시도하거나 새 미로를 생성할 수 있습니다.
- 여자·남자 탐험가를 언제든 선택할 수 있습니다. 선택은 해당 브라우저에 저장됩니다.
- 일시정지하거나 페이지를 떠나면 현재 미로와 위치, 남은 시간, 구조 상태가 저장됩니다. 다시 열면 일시정지 상태로 복구되며 `이어하기`를 눌러 재개합니다.
- 진행 상황은 현재 브라우저의 로컬 저장소에 보관됩니다. 다른 기기와의 동기화 및 Microsoft 계정 로그인은 아직 지원하지 않습니다.

## 직접 확인할 시나리오

1. 데스크톱과 모바일 화면에서 보드, HUD, 방향 버튼이 겹치지 않는지 확인합니다. 모바일에서는 버튼의 터치 입력도 확인합니다.
2. 1단계에서 동물을 구조하고 탈출구에 도착해 2단계가 열리는지 확인합니다.
3. 시간 초과 후 같은 미로 재도전과 새 미로 시작을 각각 확인합니다.
4. 플레이 중 새로고침해 일시정지 화면으로 돌아오는지, `이어하기` 후 이동할 수 있는지 확인합니다.
5. 20단계가 처음에는 잠겨 있는지 확인합니다. 오프라인 상태에서도 로컬 이미지와 이모지 대체 표시가 동작하는지 확인합니다.

# 🚀 Project Memory Starter Kit

> **"AI에게 대화창으로 매번 길게 설명하지 마세요. 파일 기반 메모리로 세션을 영구 유지하세요."**

이 스타터킷은 프로젝트에 복사해 넣는 것만으로 **3가지 전문 AI 스킬(`/grill-me`, `/memory-plan`, `/memory-execute`)**과 **파일 기반 메모리 구조**를 즉시 활성화해 주는 경량 패키지입니다.

---

## ⚡ 1분 설치법

1. 이 `project-memory-starter` 폴더 안에 있는 아래 2개 폴더를 **내 프로젝트 루트**에 복사합니다:
   - **`.agents/`**: 3대 AI 스킬 정의 폴더
   - **`.memory/`**: 메모리 파일들이 저장될 폴더

*(Cursor, Antigravity 등 스킬 지원 도구에서 즉시 슬래시 커맨드로 인식됩니다.)*

---

## 🔄 3단계 워크플로우

```text
  [1단계: 요구사항 인터뷰]        [2단계: 계획 및 청사진 생성]          [3단계: 순차 실행 및 포인터 전진]
    /grill-me <기능명>    ───→    /memory-plan <기능명>      ───→    /memory-execute (또는 "current 보고 진행해줘")
  (decisions/ 확정)              (plans/ & Task 청사진 생성)        (구현 ➔ 테스트 ➔ 커밋 ➔ 포인터 이동)
```

### 1단계: `/grill-me <기능명>`
- AI가 한 번에 딱 1개씩 추천 선택지와 함께 질문을 던집니다.
- 답변을 고르면 애매한 점이 모두 해결될 때까지 인터뷰를 진행하고, 확정된 결정을 `.memory/decisions/{기능명}.md`에 저장합니다.

### 2단계: `/memory-plan <기능명>`
- **(철칙: 이 단계에서는 코드를 전혀 작성하지 않습니다.)**
- 앞서 확정된 결정을 바탕으로 전체 계획(`plans/`), 마일스톤(`phases/`), 그리고 각 Task의 상세 스펙/테스트 명령어가 적힌 **Task 청사진(`T01...md`)**을 일괄 생성합니다.
- `.memory/current.md` 포인터를 첫 번째 작업(T01)으로 자동 초기화합니다.

### 3단계: `/memory-execute` 또는 `"current 보고 이어서 해줘"`
- `.memory/current.md`가 가리키는 Task 청사진만 읽고 정답 코드를 구현합니다.
- 테스트 커맨드를 실행하여 통과하면 자동으로 커밋하고, 상위 `phase.md` 진행률을 올린 뒤, **`current.md` 포인터를 다음 Task(T02)로 자동 전진**시킵니다.
- **퇴근 후 다음 날 새 채팅창을 열고 `"current 보고 이어서 해줘"` 한 줄만 치면 1초 만에 다음 작업으로 직행합니다.**

## 📂 폴더 구조 및 역할

```text
.memory/
├── current.md                          ← [포인터] 지금 어디를 작업 중인지 가리키는 20줄 파일
├── decisions/
│   └── YYYY-MM-DD-{기능명}.md          ← [결정] 인터뷰로 확정된 기술 결정 박제
├── plans/
│   └── YYYY-MM-DD-{기능명}.md          ← [계획] 전체 목표 및 Phase 마일스톤 목록
└── phases/
    └── YYYY-MM-DD-{기능명}/            ← [청사진] 날짜별 계획 하위 폴더
        └── P01-{마일스톤}/
            ├── phase.md                ← 진행률 대시보드
            ├── T01-{작업명}.md         ← 파일, 심볼, 모델 스키마, 테스트 커맨드
            └── T02-{작업명}.md

.agents/skills/
├── grill-me/SKILL.md                   ← 인터뷰 스킬
├── memory-plan/SKILL.md                ← 계층 계획 수립 스킬
└── memory-execute/SKILL.md             ← 순차 실행 및 포인터 전진 스킬
```
